## Sign into AKS cluster
It is advised to use a linux machine to perform your kubernetes or azure scripting. If you are working on a windows system, please consider to use WSL (Windows Subsystem Linux) Ubuntu.

#### Install kubelogin
kubelogin is an abstract layer on top of AKS that authenticates the user against AAD.

```
sudo apt install unzip
if [[ ! -f /usr/local/bin/kubelogin ]]; then
    curl -fsSLO https://github.com/Azure/kubelogin/releases/download/v0.0.28/kubelogin-linux-amd64.zip
    sudo unzip -ojd /usr/local/bin kubelogin-linux-amd64.zip bin/linux_amd64/kubelogin
    rm -f kubelogin-linux-amd64.zip
    kubelogin --version
fi
```

#### Login to AKS cluster
```
az login

az account set --subscription <subscriptionid>

az aks get-credentials --resource-group <resource group name> --name<cluster name>

az aks get-credentials --resource-group aksoc-poc-eastus-rg --name aksoc-poc-eastus

kubectl get nodes
```
Note: this updates the $HOME/.kube/config file with the login credential. If you have multiple cluster, I'd adivse you to maintain the config in different config files, and use KUBECONFIG environment variable to the one you are actvely working. This is just to ensure no accidental changes take place on unintended cluster.

```
set KUBECONFIG=$HOME/.kube/config_cluster1

set KUBECONFIG=$HOME/.kube/config_cluster1

```

## Log into AKS worker node using a POD and SSH Key
There might be times where you need to login into a node to troubleshoot issues. Hence, It is important to secure the SSH key used in building the AKS cluster. In our one cloud cluster, we have secured it in the key vault "aksoc-<env>-<location>-kv" in the "aksoc-<env>-<location>-rg" resource group.

#### Step1: 
Get the SSH Key that was used to create the AKS cluster. if you do not have it, generate a new one using the following command. 
ssh-keygen

#### Step2: 
If it's a new key you generated above, you must add the public key to the worker node pool. (use azure extension in case of AKS)

```
az vmss extension set \
--resource-group $CLUSTER_RESOURCE_GROUP\
--vmss-name <VM Scale Set Name> \
--name VMAccessForLinux  \
--publisher Microsoft.OSTCExtensions \
--version 1.4 \
--protected-settings “{\”username\”:\”azureuser\”, \”ssh_key\”:\”$(cat ~/.ssh/id_rsa.pub)\”}” 

az vmss update-instances --instance-ids ‘*’ \
--resource-group $CLUSTER_RESOURCE_GROUP \
--name $SCALE_SET_NAME
```
#### Step3: 
create a file id_rsa in the local machine and store the private key in it (you can get it from Key Vault)

#### Step4:
Create a pod aks-ssh.
```
kubectl run -it aks-ssh --image=alpine
```
#### Step5:
Copy the SSH private key file from local machine to the POD (Run it from Host machine)
```
kubectl cp ./id_rsa aks-ssh:id_rsa
```
#### Step6:
Get the Node IPs  (Run it from local machine)
```
kubectl get nodes -o wide
```
#### Step7:
Login to the POD and do SSH into the NODE VM from POD
```
kubectl exec -it aks-ssh -- /bin/sh
ssh -i id_rsa azureuser@10.240.0.33
```

## How to manage images in ACR (Azure Container Registry)
##### Reference: https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-docker-cli?tabs=azure-cli

#### Import docker images from external repository into ACR
```
// login into ACR first
az login
az account set --subscription 433cb7d3-bac1-4059-bacf-afb085b7a62b
az acr login --name aksocstgacr

// import images from docker and gcr repository
az acr import \
  --name aksocstgacr \
  --source gcr.io/google-samples/xtrabackup:1.0 \
  --image xtrabackup:1.0

az acr import \
  --name aksocstgacr \
  --source docker.io/library/mysql:5.7 \
  --image mysql:5.7

az acr import \
  --name aksocstgacr \
  --source docker.io/library/mysql:8.3 \
  --image mysql:8.3
```

#### Build an image locally and push into ACR
```
// login into ACR first
az login
az account set --subscription 433cb7d3-bac1-4059-bacf-afb085b7a62b
az acr login --name aksocstgacr

// build the docker image
docker build . -t mysqlbackup:v1
// tag the image
docker tag mysqlbackup:v1 aksocstgacr.azurecr.io/mysqlbackup:v1
// upload the image into ACR
docker push aksocstgacr.azurecr.io/mysqlbackup:v1
```

#### Copy image from one ACR to another
```
// download the image from the source ACR
az account set --subscription dc276571-9aac-4771-8451-c6ab5a4e058a 
az acr login --name aksocdevacr
docker pull aksocdevacr.azurecr.io/riskiq-stage:43762

// upload the image into the destination ACR
az account set --subscription 433cb7d3-bac1-4059-bacf-afb085b7a62b
az acr login --name aksocstgacr
docker tag aksocdevacr.azurecr.io/riskiq-stage:43762 aksocstgacr.azurecr.io/riskiq-stage:43762
docker push aksocstgacr.azurecr.io/riskiq-stage:43762
```

## Troubleshoot PODs

#### Port-forwarding
Port-forwarding is done to access a POD and service locally using local machine IP address. 

```
kubectl port-forward [resource-type]/[resource-name] [local-port]:[resource-port]

kubectl port-forward pod/secblog-56c9b7d89c-2g576 8080:80 -n secblog

kubectl port-forward service/secblog-srv  8080:80  -n secblog

kubectl port-forward service/ingress-ingress-nginx-controller  8080:80  -n ingress
```

#### Interact with a POD
You can open an interactive terminal into a POD to inspect the POD in details. 
```
kubectl exec -it pod/$POD_NAME -- /bin/sh
kubectl exec -it pod/secblog-7fc6cfb6cb-bcnn7 -n secblog -- /bin/sh

kubectl exec -it pod/aksocpoceastusbackups-backups-pvc-test-client -n base -- /bin/sh  --kubeconfig $HOME/.kube/pocconfig
```

## Troubleshoot CSI Driver
CSI (Container Storage Interface) driver is used by the AKS cluster to establish the connection to the Azure Storage (Fileshare, disk, Key Vault etc...). This section guides you on how to troubleshoot some of the known issues. 

###### Check the K8 CSI provider logs
```
kubectl get pods -l app=secrets-store-provider-azure -n kube-system -o wide
kubectl logs -l app=secrets-store-provider-azure -n kube-system --since=1h | grep ^E
```

###### Check the K8 CSI driver logs
```
kubectl get pods -l app=secrets-store-csi-driver -n kube-system -o wide
kubectl logs -l app=secrets-store-csi-driver -n kube-system --since=1h | grep ^
```

###### Cause1: "Failed to get key vault token... nmi response failed with status code: 404" error
This error occurs because a Node Managed Identity (NMI) component in aad-pod-identity returned an error for a token request.
```
Solution: Check NMI logs
https://azure.github.io/aad-pod-identity/docs/troubleshooting/

Step1: Isolate errors from log
kubectl logs -l component=mic --since=1h | grep ^E
kubectl logs -l component=nmi --since=1h | grep ^E

Step2: Run a Pod to validate identity
kubectl run azure-cli -it --image=mcr.microsoft.com/azure-cli --labels=aadpodidbinding=<selector defined in AzureIdentityBinding> /bin/bash
# within the azure-cli shell
az login --identity --allow-no-subscriptions --debug
```

###### Cause2: "keyvault.BaseClient#GetSecret: Failure sending request: StatusCode=0" error
```
Solution: Check network policies, allowlist, and node connection
To fix the issue, take the following actions:
    - Put the provider pods on the allowlist.
    - Check for policies that are configured to block traffic.
    - Make sure that the node has connectivity to Microsoft Entra ID and your key vault.

Step1: Create a POD
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata:
  name: curl
spec:
  hostNetwork: true
  containers:
  - args:
    - tail
    - -f
    - /dev/null
    image: curlimages/curl:7.75.0
    name: curl
  dnsPolicy: ClusterFirst
  restartPolicy: Always
EOF

Step2: Run kubectl exec to run a command in the pod that you created:
kubectl exec -it curl -- sh

Step3: Authenticate with your Azure key vault:
curl -X POST 'https://login.microsoftonline.com/<AAD_TENANT_ID>/oauth2/v2.0/token' \
     -d 'grant_type=client_credentials&client_id=<AZURE_CLIENT_ID>&client_secret=<AZURE_CLIENT_SECRET>&scope=https://vault.azure.net/.default'


Step4: Try to get a secret that's already created in your Azure key vault:
curl -X GET 'https://<KEY_VAULT_NAME>.vault.azure.net/secrets/<SECRET_NAME>?api-version=7.2' \
     -H "Authorization: Bearer <ACCESS_TOKEN_ACQUIRED_ABOVE>" 
```

# Upgrade API
AKS releases newer version of API and deprecate old ones which could impact the client operation. Hence, you must know how to find the API versions in use.
```bash
# command to find the list of API used in last 30 days.
az monitor activity-log list --offset 30d --max-events 10000 --namespace microsoft.containerservice --query "[?eventName.value == 'EndRequest' && not_null(httpRequest.uri)].{Name: claims.name, URI: httpRequest.uri, LocalizedOperation: operationName.localizedValue, OperationValue: operationName.value}" --output table

# Find the unique APIs in use with the type of operation
az monitor activity-log list --offset 90d --max-events 10000 --namespace microsoft.containerservice --query "[?eventName.value == 'EndRequest' && not_null(httpRequest.uri) && contains(httpRequest.uri, '-preview')].httpRequest.uri" --output tsv | sort | uniq > /mnt/c/Users/v-bimishra/workspace/aksscripts/api_list.tsv

# Write the list into tsv file
az monitor activity-log list --offset 90d --max-events 10000 --namespace microsoft.containerservice --query "[?eventName.value == 'EndRequest' && not_null(httpRequest.uri) && contains(httpRequest.uri, '-preview')].{Name: claims.name, URI: httpRequest.uri, LocalizedOperation: operationName.localizedValue, OperationValue: operationName.value}" --output tsv > /mnt/c/Users/v-bimishra/workspace/aksscripts/activity_log.tsv
```
- For Azure CLI: Update the CLI itself and the aks-preview extension (if used) to the latest version by running az upgrade and az extension update --name "aks-preview".

- For Terraform: Update to the latest version of the AzureRM Terraform module. To find out what version of the API a particular Terraform release is using, check the Terraform release notes or git log this file.

- For Azure SDKs: use a newer API version by updating to a newer version of the SDK.
