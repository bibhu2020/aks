# Security Context vs Service Account
A ServiceAccount is used to determine the permissions that the pod has to interact with the Kubernetes API and other cluster resources. It does not directly affect the security settings of the containers running within the pod.

The securityContext allows you to define security settings at the container level, such as:
- Privileged mode: Whether the container has elevated privileges.
- Linux capabilities: Fine-grained control over which capabilities the container can use.
- SELinux or AppArmor profiles: Mandatory access control policies.
- UID and GID: The user and group IDs under which the container runs.
- Resource limitations: CPU and memory limits and requests.
