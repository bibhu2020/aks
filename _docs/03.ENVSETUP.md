## Setting up Staging
One Cloud staging environment is a single cluster (no DR) setup with mysql database running within the cluster itself. This is done intentionally to lower the staging environment cost

### Setup Kured
##### Add the Kured Helm repository
helm repo add kubereboot https://kubereboot.github.io/charts/

##### Update your local Helm chart repository cache
helm repo update

##### Create a dedicated namespace where you would like to deploy kured into
kubectl create namespace kured

##### Install kured in that namespace with Helm 3 (only on Linux nodes, kured is not working on Windows nodes)
helm install my-release kubereboot/kured --namespace kured --set controller.nodeSelector."kubernetes\.io/os"=linux

## Setting up PPE (Pre-Production)
One Cloud pre-production environment is intended to be an exact replica of the production. It has two AKS cluster running in tandem with one being primary in eastus region and other being the secondary in the westus region. Both the cluster operate in active-active mode and connect to mysql service hosted using Azure MySQL Flexible server. Purposefully, the database has setup outside the cluster so that both the cluster can connect to it. And ofcourse the burden of db management, patching, and replication admin activities are off-loaded from the SRE team by doing this.

## Setting up PRD (Production)
One Cloud production environment has two AKS cluster running in tandem with one being primary in eastus region and other being the secondary in the westus region. Both the cluster operate in active-active mode and connect to mysql service hosted using Azure MySQL Flexible server.
